### 1.2 Affliction status palette — colour-blind safe by construction

The safety guarantee is **not** hue separation. It is that _every_ status carries three independent channels: **hue**, **an ASCII badge glyph**, and **a fill pattern**. Any one alone is sufficient to identify the status. Hues are adapted from the Okabe–Ito CVD-safe set, brightened for a near-black ground.

| Status             | Token                 | Hex       | Badge glyph             | Pattern                     | Phase       |
| ------------------ | --------------------- | --------- | ----------------------- | --------------------------- | ----------- |
| **Null / missing** | `--w1-status-null`    | `#C77DFF` | literal `NaN` cell text | 45° hatch, 6px pitch        | **Phase 1** |
| Duplicate          | `--w1-status-dup`     | `#6FC8FF` | `=`                     | horizontal 3px bands        | Phase 2     |
| Wrong dtype        | `--w1-status-dtype`   | `#F0E442` | `#`                     | 3px dotted underline        | Phase 2     |
| Whitespace/casing  | `--w1-status-ws`      | `#5DD9C1` | `_`                     | leading/trailing tick marks | Phase 2     |
| Outlier            | `--w1-status-outlier` | `#FF9E4A` | `^`                     | 135° hatch, 6px pitch       | Phase 2     |
| Bad date           | `--w1-status-date`    | `#F58FD0` | `@`                     | vertical 3px bands          | Phase 2     |

Define all six now in `theme.css` so Phase 2 does not re-open the palette. **Only `--w1-status-null` is rendered in Phase 1.**

Violet against a green/amber phosphor base is deliberate: it is a colour the terminal "shouldn't be able to make." The affliction reads as foreign to the machine.

### 1.3 Diff palette

Git's red/green is a colour-blind trap on its own. Mitigations, all mandatory:

1. Deletion is **vermillion-orange `#FF6B3D`**, not pure red — separable from `#35F06B` under deuteranopia and protanopia.
2. Every diff line and every flashed cell carries a literal `-` / `+` gutter glyph, exactly as `git diff` does.
3. Deleted values are struck through; added values are not.

```css
[data-world="boss-fights"] {
  --w1-diff-del: #ff6b3d;
  --w1-diff-del-rgb: 255 107 61;
  --w1-diff-add: #35f06b;
  --w1-diff-add-rgb: 53 240 107;
  --w1-diff-peak: 0.3; /* peak background alpha of a diff flash */
}
```

## 2. Typography

Two monospace faces, both SIL OFL 1.1, both self-hosted from npm (mandatory: `vercel.json` sets `font-src 'self'` — no Google Fonts CDN, no `<link>` to a third-party origin).

| Role                                                                        | Family                               | Package                             |
| --------------------------------------------------------------------------- | ------------------------------------ | ----------------------------------- |
| **Display** — boss title, HUD labels, grid headers, run button, status rail | **Martian Mono** (Evil Martian, OFL) | `@fontsource-variable/martian-mono` |
| **Text/code** — briefing, editor, cell values, console, ASCII sigil         | **IBM Plex Mono** (IBM, OFL)         | `@fontsource/ibm-plex-mono`         |

Neither is the system default; Martian Mono in particular is mechanical and wide, which gives display type a hard industrial voice that no default sans or JetBrains-Mono-by-reflex choice provides. The two are separable at a glance because their advance widths differ dramatically.

```css
[data-world="boss-fights"] {
  --w1-font-display:
    "Martian Mono Variable", "Martian Mono", "IBM Plex Mono", ui-monospace, monospace;
  --w1-font-text:
    "IBM Plex Mono", ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
}
```

**Loading:** import in `apps/web/src/worlds/boss-fights/index.ts` — `latin` subset only, weights `400 500 600` for Plex Mono, the variable file for Martian Mono, `font-display: swap`. Do not import the full multi-subset bundle; it is ~10× the payload for no benefit.

**Fallback if `@fontsource-variable/martian-mono` is unavailable at install time:** use `@fontsource/martian-mono` static weights `600` and `700`, and drop all `font-variation-settings` declarations below. Do not substitute a different typeface.

**Global features** on the world root: `font-variant-ligatures: none;` (code ligatures are a readability liability in a data grid and break ASCII art alignment), `font-feature-settings: "zero" 1;` (slashed zero — this is a numeric dataset).

## 3. Screen layout

**One screen. Two states.** `boot` → `fight`. No routing between them; a single `<BossFightScreen>` with a boolean.

### 3.1 Global frame rules

- The world root sets `height: 100dvh; overflow: hidden;` at ≥1080px. The page never scrolls; panels scroll internally. This is the single biggest thing separating this from a document-shaped marketing page.
- `border-radius: 0` **everywhere** — enforced with `[data-world="boss-fights"] * { border-radius: 0; }` in `theme.css`. No exceptions, including the run button and scrollbars.
- `box-shadow` with a blur radius > 0 is **banned**. Depth comes from 1px rules plus background steps. Where a raised affordance is genuinely needed, use a hard offset: `box-shadow: 2px 2px 0 #000`.
- Panels are separated by `1px solid var(--w1-rule-strong)` borders, not gaps. Grid `gap: 0`.
- Custom scrollbars: `scrollbar-width: thin; scrollbar-color: var(--w1-rule-strong) transparent;` plus `::-webkit-scrollbar { width: 10px }`, thumb `--w1-rule-strong`, no radius.
- z-index scale: `0` panels · `10` sticky grid header + index gutter · `20` persistent diff outline · `30` focus ring · `60` boot screen · `90` CRT overlay (`pointer-events: none`).

### 3.2 Boot / title state

Not a hero. A boot log. Full-bleed `--w1-bg-void`, content block left-aligned, positioned at `padding: 12vh 0 0 8vw`, `max-width: 62ch`.

Lines type out sequentially. Typing is a GSAP tween on `{ i: 0 } → { i: line.length }` with `snap: { i: 1 }`, `onUpdate` writing `el.textContent = line.slice(0, i)` — **no TextPlugin dependency**. `22ms` per character; each line starts `90ms` after the previous line finishes. A `_` cursor block (Plex Mono, `--w1-green-500`) blinks at 530ms on / 530ms off on the active line only.

```
DCQ//BOOT  v0.1.0
mounting engine ......... pyodide/wasm      OK
loading dataset ......... nul_sentinel.csv  240x6   OK
scanning for affliction .. NUL   023 CELLS  DETECTED

[ ENTER ]  engage NUL_SENTINEL
```

- Colour: lines 1–3 `--w1-text-secondary`, the `OK` tokens `--w1-green-500`, `023 CELLS  DETECTED` `--w1-status-null`, the final prompt `--w1-amber-500`.
- Total run time ≈ 2.4s. **Any keypress or click skips to the end state immediately.** `Enter` (or click) from the end state transitions to `fight`.
- Transition to fight: boot block `opacity 1 → 0` over 180ms `power1.in`; fight layout `opacity 0 → 1` over 260ms `power2.out` starting at 120ms (overlap). No slide, no scale.
- Under `prefers-reduced-motion: reduce`: all lines render instantly, whole block fades in over 400ms, cursor does not blink (static, 60% opacity). `Enter` is still required — never auto-skip a state the user might be reading.
- The boot screen is **not** focus-trapped beyond a single `<button>` labelled "Engage NUL_SENTINEL" that is visually the `[ ENTER ]` line, so keyboard and screen-reader users get a real control.

### 3.4 Where diff feedback appears — both places, deliberately

1. **On the grid**, as the cell flash (§7) — this is the "watch your data change" payoff.
2. **In the console** as `-`/`+` lines — this is the transferable skill (reading a diff), and it is the only durable record after the flash decays.

They are driven by the same change list. Do not build two sources of truth.

### 3.5 Responsive collapse

- **< 1080px:** `.stage` becomes `grid-template-columns: 1fr`; the world root drops `overflow: hidden` and the page scrolls. Source order must already be: status rail → briefing → HP band → grid → editor → run bar → console. Use `order` on `.commandRail` children if needed, but prefer emitting the panels as siblings of `.stage` in that DOM order and letting the two-column layout reassemble them via `grid-template-areas` — DOM order should match the narrow reading order, not the wide one.
  - Grid gets `height: 46vh; min-height: 300px`.
  - Editor gets `min-height: 220px`.
- **< 720px:** additionally render a one-line amber notice directly under the status rail: `NARROW DISPLAY // EDITOR IS CRAMPED BELOW 720PX`, `--w1-amber-500` on `--w1-bg-panel-2`, dismissible. Everything remains functional. Do not block, do not show a "please use desktop" wall.

### 3.6 Keyboard & screen reader

- `Cmd/Ctrl+Enter` runs the code (registered in the CodeMirror keymap, not a window listener).
- `Escape` inside the editor moves focus to the run button (standard editor-escape-hatch pattern; without it the editor is a Tab trap).
- Tab order: status rail controls → briefing (scrollable region, `tabindex="0"`) → editor → run button → console (scrollable region) → HP meter → grid.
- Grid is `role="grid"` with roving `tabindex` on cells; arrow keys move the roving focus. Afflicted cells get `aria-label="temp_c, row 14, missing value"`. Clean cells get no `aria-label` (value text is sufficient).
- HP strip: `role="meter" aria-valuemin="0" aria-valuemax="23" aria-valuenow="23" aria-label="Afflicted cells remaining"`.
- One `aria-live="polite"` region announces **summaries only**, debounced 400ms: `"Run complete. 23 cells changed. 0 afflicted cells remaining."` The per-line diff log is `aria-live="off"` inside a readable scroll region — announcing 23 individual diff lines would flood a screen reader into uselessness.
- Errors announce via `aria-live="assertive"`: `"Run failed. NameError on line 3."` followed by the full traceback available in the readable region.

### 4.1 Motion layers (GSAP-driven, see §8)

- **Flicker:** `--w1-crt-opacity` oscillates `1 → 0.965 → 1` on an irregular timeline (`gsap.timeline({repeat:-1}).to(…, {duration: gsap.utils.random(0.08, 0.5, 0.01, true)})`). Perceptually a phosphor instability, not a strobe. **Never drops below 0.94** — a hard floor so the effect can't read as flashing content (WCAG 2.3.1 safety margin; the effect is also far below the 3Hz general-flash threshold by construction, since minimum tween duration is 80ms and amplitude is 3.5%).
- **Roll bar:** a `140px`-tall soft band (`linear-gradient(to bottom, transparent, rgb(255 255 255 / 0.025), transparent)`) inside `.crt`, translated `-140px → 100vh` over `9s`, `ease: "none"`, `repeat: -1`, `repeatDelay: 6`.

### 4.2 Back-off — three independent switches

These are orthogonal. A user may want motion reduced but scanlines kept, or the reverse.

| Trigger                                        | Effect                                                                                                                                                                                                                                      |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@media (prefers-reduced-motion: reduce)`      | Flicker timeline killed (`--w1-crt-opacity: 1` fixed). Roll bar killed and removed from DOM. **Static scanlines, grille, and vignette all remain** — they are texture, not motion.                                                          |
| `[data-dcq-intensity="reduced"]` (user toggle) | `.crt { display: none }`. All three alphas set to `0`. Independent of any motion preference.                                                                                                                                                |
| `[data-dcq-contrast="high"]`                   | Forces `.crt { display: none }` regardless of the intensity toggle. High contrast wins.                                                                                                                                                     |
| `@media (forced-colors: active)`               | `.crt { display: none }`. All decorative backgrounds drop; the grid falls back to `Canvas`/`CanvasText`/`Highlight` system colours, and affliction identity rests entirely on the literal `NaN` text plus a `2px dashed CanvasText` border. |

**Default state of the intensity toggle:** ON (scanlines visible), **except** it initialises to `reduced` automatically if `matchMedia('(prefers-contrast: more)')` or `matchMedia('(prefers-reduced-transparency: reduce)')` matches on first load. The user's explicit choice, once made, always wins and persists.

### 4.3 The legibility guarantee

The CRT overlay is decorative and may never be the difference between readable and unreadable. Concretely:

- Scanline alpha is capped at `0.28` (`0.22` at ≥2dppx) — verified in §1.5.
- The overlay applies to the _whole viewport uniformly_; it never sits on top of an already low-contrast element in a way that compounds.
- The overlay is `pointer-events: none` and `aria-hidden` — it can never intercept input or reach assistive tech.
- Text is **never** rendered with `text-shadow` glow as a substitute for weight or contrast. The only `text-shadow` in this spec is the transient chromatic-aberration on recoil (§8a), which is ≤200ms and disabled under reduced motion.

### 4.4 Accessibility control cluster

Right side of the status rail. Five `28×28px` buttons, `1px solid var(--w1-rule-strong)`, `background: transparent`, `color: var(--w1-text-secondary)`, display face 10px. Hover/focus: `border-color: var(--w1-amber-500); color: var(--w1-amber-500)`.

| Control    | Label | Effect                                                                                                 |
| ---------- | ----- | ------------------------------------------------------------------------------------------------------ |
| Font down  | `A-`  | steps `--dcq-text-scale` down through `1.25 → 1.125 → 1 → 0.875`                                       |
| Font reset | `A`   | sets `--dcq-text-scale: 1`                                                                             |
| Font up    | `A+`  | steps up                                                                                               |
| Intensity  | `CRT` | toggles `data-dcq-intensity` between unset and `"reduced"`; pressed state = `aria-pressed`, amber fill |
| Contrast   | `HC`  | toggles `data-dcq-contrast="high"`; `aria-pressed`                                                     |

All three attributes live on `<html>`, and the whole cluster's state persists to `localStorage` under key **`dcq.a11y`** — a key deliberately separate from the (Phase 2) save file, so clearing progress never resets someone's accessibility settings. Each button needs a real `aria-label` ("Increase text size", "Toggle CRT effect", "High contrast mode"); the two-character labels are visual only.

Changing `--dcq-text-scale` must call `virtualizer.measure()` (§3.3).

## 5. Affliction cell rendering

### 5.1 Markup

The virtualizer renders every cell identically. Affliction is applied by **direct DOM mutation** after render (ADR 0001 guardrail 2) — a small `applyAffliction(cellEl, status, seed)` in `worlds/boss-fights/afflictionDom.ts`, called from the virtualizer's row-render callback and from the post-run reconciliation. It sets attributes and CSS vars only; it never triggers React.

```html
<div
  class="cell"
  role="gridcell"
  data-affliction="null"
  style="--w1-cell-seed: 6"
  aria-label="temp_c, row 14, missing value"
>
  NaN
</div>
```

`--w1-cell-seed` is `rowIndex % 16`.

### 5.2 Rest state — three independent signals

**Signal 1 — the value itself.** The cell renders the literal string `NaN`, in `--w1-status-null`, weight `500`, `letter-spacing: 0.02em`. This is the strongest non-colour signal available and it is free: it is exactly what pandas prints. Never replace it with an icon.

**Signal 2 — 45° hatch pattern.** Static, non-animated.

**Signal 3 — dashed border.** `1px dashed`, distinguishing afflicted cells from clean cells (which have no border, only the column separator) in pure greyscale.

The **colour wash** is the fourth, animated channel — pleasant but redundant.

```css
.cell[data-affliction="null"] {
  position: relative;
  color: var(--w1-status-null);
  font-weight: 500;
  border: 1px dashed rgb(var(--w1-status-null-rgb) / 0.55); /* signal 3 */
  will-change: opacity;
}

/* signal 4 — the pulsing wash */
.cell[data-affliction="null"]::before {
  content: "";
  position: absolute;
  inset: 0;
  background: rgb(var(--w1-status-null-rgb) / 1);
  opacity: 0.1;
  animation: w1-affliction-pulse 2200ms cubic-bezier(0.45, 0, 0.55, 1) infinite;
  animation-delay: calc(var(--w1-cell-seed, 0) * -137ms);
  pointer-events: none;
}

/* signal 2 — the hatch */
.cell[data-affliction="null"]::after {
  content: "";
  position: absolute;
  inset: 0;
  background: repeating-linear-gradient(
    45deg,
    transparent 0 5px,
    rgb(var(--w1-status-null-rgb) / 0.3) 5px 6px
  );
  pointer-events: none;
}

@keyframes w1-affliction-pulse {
  0%,
  100% {
    opacity: 0.1;
  }
  50% {
    opacity: 0.26;
  }
}
```

### 5.3 Why the pulse is CSS, not GSAP

This is the one animation in World 1 that is **not** GSAP, and the reason must be understood before changing it: afflicted cells are created and destroyed constantly by virtualization scroll recycling. A GSAP tween would need registering and killing per cell on every recycle — a leak and a bookkeeping cost for an ambient idle effect. A declarative CSS animation attaches and detaches with the element for free. GSAP owns every _event-driven_ animation (§8); CSS owns this one _ambient_ one. Do not blur that line.

The negative `animation-delay` keyed off `--w1-cell-seed` desynchronises cells across a 16-step cycle, so the grid flickers organically rather than breathing in unison — the difference between "a screen with a fault in it" and "a generic pulsing highlight."

### 5.4 Overrides

```css
@media (prefers-reduced-motion: reduce) {
  .cell[data-affliction="null"]::before {
    animation: none;
    opacity: 0.2; /* the midpoint — the signal is never silently lost */
  }
}

[data-dcq-contrast="high"] .cell[data-affliction="null"] {
  border: 2px solid var(--w1-status-null);
}
[data-dcq-contrast="high"] .cell[data-affliction="null"]::before {
  opacity: 0.14;
}
[data-dcq-contrast="high"] .cell[data-affliction="null"]::after {
  display: none;
}
```

Under high contrast the hatch is dropped (it competes with text at high alpha) and replaced by a solid 2px border — signal count stays at three.

### 5.5 Cleared-state transition

1. Post-run reconciliation sets `data-affliction="none"` and `data-just-cleared="true"` on the cell, and writes the new value into `.diffNew`.
2. GSAP runs the diff-flash timeline (§7).
3. Removing `data-affliction="null"` detaches the pulse animation and both pseudo-elements instantly. To avoid a hard pop, the hatch and dashed border are cross-faded out _inside_ the flash timeline instead: keep `data-affliction="null"` for the first 320ms of the flash, then swap to `none` at the exact frame the new value reaches full opacity — the flash's own background covers the transition. Implement as an `onComplete` on the flash's step-4 tween.
4. `data-just-cleared="true"` persists a `1px solid rgb(var(--w1-diff-add-rgb) / 0.35)` outline (`z-index: 20`) on the cell for the remainder of the turn — a ledger mark showing what you touched. It is cleared at the start of the next run.

## 6. HP heatmap strip

### 6.1 Decision: per-row segments, auto-binned — not an aggregate bar

The strip is a **minimap of the dataframe's affliction distribution**, not a game HP gauge. This matters: the nulls in this dataset are clustered (§0), so the strip visibly shows _where_ the damage is, and the player watches specific regions go dark. That is a real, transferable read of a dataset. An aggregate bar teaches nothing and is the generic game-HUD default.

**Binning:** let `W` = strip width in px, `N = min(rowCount, floor(W / 4))`. Each segment is `3px` wide with a `1px` gap (4px pitch). Rows map to segments by `floor(rowIndex * N / rowCount)`. Each segment's intensity = `afflictedInBin / rowsInBin`.

At 1440px viewport the strip is ≈ 640px wide → `N = 160` segments for 240 rows (1–2 rows per bin). Cap `N` at 240.

### 6.2 Rendering

DOM `<i>` elements, not canvas — GSAP needs per-segment transforms for the shatter, and 160–240 tiny absolutely-positioned elements is well within budget.

- `.hpDenom`: HUD-label type, `--w1-text-dim`, `margin-left: 8px`.
- At zero, `.hpNum` becomes `000` in `--w1-green-500` and `.hpLabel` changes to `HULL INTEGRITY  RESTORED`.

### 6.4 Communicating "23 remaining, decreasing"

Four simultaneous reads, no single point of failure:

1. **Count** — the literal `023` readout, GSAP-tweened downward (§8b), so the number visibly _rolls_ rather than snapping.
2. **Silhouette** — cleared segments drop from 18px to 6px; the profile of the bar visibly flattens.
3. **Colour** — cleared segments desaturate down the violet ramp to `--w1-rule-faint`.
4. **Event** — the shatter (§8b) makes the _moment_ of the decrease legible, not just the before/after states.

## 7. Diff-flash mechanics

Per-cell timeline, **720ms total**. The cell contains two absolutely-stacked spans, both present in the DOM before the timeline starts:

```html
<div class="cell" data-affliction="null">
  <span class="diffGutter">-</span>
  <span class="diffOld">NaN</span>
  <span class="diffNew" style="opacity:0">22.4</span>
</div>
```

`.diffGutter` is `position: absolute; left: 2px; width: 8px;` — the `-`/`+` glyph, 11px, matching the current phase colour. This is the git-diff literacy signal and the colour-blind guarantee.

### 7.1 Sequence

| Phase          | Window            | What happens                                                                                                                                                     | Ease           |
| -------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| **1. Mark**    | 0 ms              | `--w1-diff-color` set to `--w1-diff-del`; gutter glyph `-`; `.diffOld` gets `text-decoration: line-through`                                                      | —              |
| **2. Delete**  | 0–140 ms          | Cell bg `--w1-diff-alpha: 0 → 0.30`. `.diffOld` `opacity 1 → 0`, `y: 0 → -6px`                                                                                   | `power2.out`   |
| **3. The cut** | 140–160 ms        | 20 ms of nothing. Both spans invisible.                                                                                                                          | —              |
| **4. Insert**  | 160–320 ms        | `.diffNew` `opacity 0 → 1`, `y: 6px → 0`. Gutter swaps `-` → `+`. `--w1-diff-color` crossfades del → add. Affliction attribute swaps to `none` at 320 ms (§5.5). | `power3.out`   |
| **5. Hold**    | 320–480 ms        | `--w1-diff-alpha` holds at `0.30`. The readable beat — the player gets 160 ms to actually see the new value against a green field.                               | —              |
| **6. Settle**  | 480–720 ms        | `--w1-diff-alpha: 0.30 → 0`. `.diffNew` colour `--w1-green-500 → --w1-text-primary`.                                                                             | `power1.inOut` |
| **7. Ledger**  | 720 ms → next run | 1px `rgb(var(--w1-diff-add-rgb) / 0.35)` outline persists (§5.5 step 4).                                                                                         | —              |

The 20ms cut in phase 3 is the signature beat. Without it a crossfade reads as a smooth blend; with it the change reads as a _cut_ — a discrete edit, which is what it is.

The cell background is driven by two CSS vars so GSAP touches only compositor-cheap custom properties:

```css
.cell {
  background-color: rgb(var(--w1-diff-color, 0 0 0) / var(--w1-diff-alpha, 0));
}
```

### 7.2 Staggering multiple changes

Order: **reading order** — ascending `(rowIndex, columnIndex)`. The wave travels top-to-bottom down the grid, the same direction the eye scans, so 23 simultaneous changes read as a sweep rather than static.

```
each = min(26, 900 / changedCellCount)   // ms
total wave ≤ 900ms + 720ms cell duration = 1620ms worst case
```

At 23 cells: `each = 26ms`, wave spans 598ms. At 200 cells: `each = 4.5ms`.

Deliberate contrast with the HP shatter, which staggers `from: "random"` (§8b). Ordered wave on the data = comprehension; chaotic scatter on the HP bar = impact. They should not feel like the same effect.

### 7.3 Off-screen changes

Only cells currently rendered by the virtualizer get the flash timeline. Off-screen changes are applied to the data model immediately and **not** queued — replaying a flash on scroll would be misleading (the change did not happen then). Off-screen cells that changed in the current turn receive the phase-7 ledger outline on mount, so scrolling after a run still shows what you touched.

Cells that scroll into view _during_ the wave (the user scrolled mid-animation) join at the current wave position, not from the start.

## 8. GSAP choreography

All of it lives in `apps/web/src/anim/world1/`:

```
anim/world1/
├── battlefieldRecoil.ts   (a)
├── hpShatter.ts           (b)
├── diffFlash.ts           (c)
├── crtIdle.ts             (§4.1)
├── bootType.ts            (§3.2)
└── motionContext.ts       shared gsap.matchMedia() + reduced-motion helpers
```

**Universal rules:**

- Every animation is built inside `gsap.matchMedia()` with `(prefers-reduced-motion: reduce)` and `(prefers-reduced-motion: no-preference)` branches. This is the idiomatic GSAP mechanism and it handles the user _changing_ the preference live, which a one-time `matchMedia` read does not.
- Components use `useGSAP()` from `@gsap/react`, scoped to a container ref, so StrictMode double-invoke and unmount cleanup are handled.
- Targets are acquired via refs or `gsap.utils.toArray()` within the scope. **No component ever calls `setState` to drive an animation frame.**
- Numeric readouts are tweened on a plain object and written with `onUpdate: () => { el.textContent = … }`. This is the specific pattern ADR 0001 exists to protect.
- Only `transform`, `opacity`, and CSS custom properties are animated. No `width`/`height`/`top`/`left`.

### (a) Boss-hit recoil

**The grid is the boss**, so the boss recoils by the `.battlefield` element recoiling. There is no sprite to hit.

- **Target:** `.battlefield` (wraps HP band + grid, so they take the hit together as one physical object).
- **Trigger:** a run that reduced the affliction count by ≥1. A run that changes cells but clears nothing gets no recoil (see below).
- **Amplitude scales with damage:** `amp = gsap.utils.clamp(4, 14, 9 * (clearedThisTurn / totalAffliction))` px.

```
tl = gsap.timeline()
tl.to(el, { x: -amp,      skewX: 1.2,  duration: 0.07, ease: "power4.out" })
  .to(el, { x:  amp*0.45, skewX: 0.4,  duration: 0.04, ease: "power2.inOut" })
  .to(el, { x:  0,        skewX: 0,    duration: 0.31, ease: "elastic.out(1, 0.45)" })
```

Parallel, from t=0:

- `--w1-chromatic`: `0 → 2.5 → 0` over 200 ms, `power2.out` then `power2.in`. Applied as a text-shadow on grid text:
  `text-shadow: calc(var(--w1-chromatic,0) * -1px) 0 rgb(255 0 80 / 0.6), calc(var(--w1-chromatic,0) * 1px) 0 rgb(0 200 255 / 0.6);`
  This is a CRT electron-beam deflection artifact — the screen mis-converges under the impact. It is the detail that makes this read as a specific machine being struck rather than a generic shake.
- `.crt` `--w1-crt-opacity`: `1 → 0.55 → 1` over 90 ms — the screen blooms on impact.

Total 420ms. The three-stage arc (hard hit → small overshoot → elastic settle) is the personality; a single `x: -8, yoyo: true` shake is the generic version and is not acceptable.

**No-progress run:** if code ran successfully but cleared zero cells, there is no recoil. Instead the `.battlefield` border flashes `--w1-amber-500` once over 200ms and the console prints `no change — 023 afflicted cells remain`. Silence would read as a bug.

**Reduced motion:** no `x`, no `skewX`, no chromatic aberration, no CRT bloom. Replace with:

```
tl.to(el, { "--w1-hit-tint": 0.18, duration: 0.10, ease: "power2.out" })
  .to(el, { "--w1-hit-tint": 0,    duration: 0.16, ease: "power1.inOut" })
```

where `.battlefield { background-color: rgb(var(--w1-diff-add-rgb) / var(--w1-hit-tint, 0)); }` and the border colour cross-fades `--w1-rule-strong → --w1-green-500 → --w1-rule-strong` over 260ms. Colour and opacity only, zero displacement. **The feedback is not removed, only its motion.**

### (b) HP segment shatter

**Trigger:** any segment whose `data-level` decreases.

Per shattering segment, two parallel tweens:

**Shards** (the three `<b>` children, which fall off the bar):

```
gsap.set(shards, { visibility: "visible" })
gsap.to(shards, {
  y:        () => gsap.utils.random(18, 30),
  x:        () => gsap.utils.random(-9, 9),
  rotation: () => gsap.utils.random(-80, 80),
  opacity:  0,
  duration: 0.42,
  ease:     "power2.in",          // gravity — they fall, they don't float
  stagger:  { each: 0.02, from: "random" },
  onComplete: () => gsap.set(shards, { visibility: "hidden", clearProps: "transform,opacity" })
})
```

**The segment body** collapsing to its new height:

```
gsap.fromTo(seg,
  { scaleY: 1 },
  { scaleY: newHeight / oldHeight, duration: 0.28, ease: "back.in(2.2)",
    transformOrigin: "bottom center" })
```

`back.in(2.2)` makes it stretch _up_ fractionally before snapping down — a crack, then a collapse. That inversion is what makes it read as breakage rather than draining. Height changes are done with `scaleY` on a fixed-height element, never by animating `height` — the strip has up to 240 siblings and a layout animation would thrash.

**Across segments:** `stagger: { each: 0.018, from: "random" }`. Random ordering is deliberate — see §7.2.

**Colour:** the segment's `--seg-color` tweens to the new level's colour over `0.30s`, `power1.inOut`, running under the collapse.

**Counter:**

```
const c = { v: prevCount };
gsap.to(c, {
  v: nextCount, duration: 0.5, ease: "power2.out", snap: { v: 1 },
  onUpdate: () => { numEl.textContent = String(Math.round(c.v)).padStart(3, "0"); },
  onComplete: () => { meterEl.setAttribute("aria-valuenow", String(nextCount)); }
});
```

`aria-valuenow` updates once, on completion — not every frame, which would spam assistive tech.

**Reduced motion:** no shards (`visibility` stays hidden), no `back.in`. Segment `scaleY` transitions linearly over `0.30s` `ease: "none"`, `--seg-color` cross-fades over the same window, counter is set instantly (`gsap.set`) rather than tweened. The bar still visibly drops and recolours; only the breakage theatre is gone.

### (c) Diff flash

The §7 timeline, expressed as GSAP. Animated properties: `.diffOld` → `opacity`, `y`; `.diffNew` → `opacity`, `y`, `color`; the cell → `--w1-diff-alpha` and `--w1-diff-color` (GSAP's core CSSPlugin animates custom properties directly — no extra plugin registration needed).

```
const tl = gsap.timeline();
tl.set(cell,  { "--w1-diff-color": "var(--w1-diff-del-rgb)" })
  .set(gutter,{ textContent: "-" })
  .to(cell,   { "--w1-diff-alpha": 0.30, duration: 0.14, ease: "power2.out" }, 0)
  .to(old,    { opacity: 0, y: -6,       duration: 0.14, ease: "power2.out" }, 0)
  // 0.14 → 0.16 : the cut. no tween.
  .set(gutter,{ textContent: "+" }, 0.16)
  .set(cell,  { "--w1-diff-color": "var(--w1-diff-add-rgb)" }, 0.16)
  .fromTo(nu, { opacity: 0, y: 6 },
              { opacity: 1, y: 0, duration: 0.16, ease: "power3.out" }, 0.16)
  // 0.32 → 0.48 : hold
  .to(cell,   { "--w1-diff-alpha": 0, duration: 0.24, ease: "power1.inOut" }, 0.48)
  .to(nu,     { color: "var(--w1-text-primary)", duration: 0.24, ease: "power1.inOut" }, 0.48);
```

Master timeline with the stagger from §7.2:

```
master.add(() => buildCellTimeline(cell), i * eachMs / 1000)
```

Use a single master timeline for the whole turn so it can be killed cleanly if the user runs again mid-animation (`master.kill()` then `gsap.set(cells, { clearProps: "all" })` before starting the next turn).

**Reduced motion:**

- Remove all `y` translations.
- Remove the 20 ms cut; old and new cross-fade over a single 240 ms `power1.inOut` window.
- Peak `--w1-diff-alpha` drops from `0.30` to `0.18`, held longer (total 600 ms) so the change is still readable without a fast luminance swing.
- Gutter glyph swap is unchanged — it is text, not motion, and it is the primary signal.
- Stagger `each` drops to `12 ms`, total wave capped at `400 ms`.

Everything the flash communicates — what was there, what is there now, that it changed — survives. Only motion is removed.

### 8.1 Performance budget

Concurrent tween ceiling on a heavy turn: ~23 cell timelines × 3 targets + ~40 HP segment tweens + 1 recoil ≈ 130 tweens. Well within GSAP's headroom. All animated properties are `transform`, `opacity`, or custom properties feeding `background-color`/`color`. If a turn would exceed **300** concurrent cell timelines, fall back to instant-apply plus a single whole-grid `--w1-diff-alpha` pulse — do not attempt to stagger 1000 cells.

## 9. ASCII-block boss art

### 9.1 Concept: the decaying sigil

The dataframe is the boss (plan §5), so the ASCII art must not compete with it. This is a **13×6 character sigil** in the briefing header — an 88×66px flavour mark, not a figure.

What makes it earn its place rather than being decoration: **it is bound to game state.** The sigil is a frame with a fill interior, and the fill characters step down a density ramp as the affliction clears. The boss is literally made of the missing data, and it thins out as you fill the gaps. At victory the frame remains, empty.

### 9.2 The art

Structure — frame characters never change:

```
+===========+
| ##     ## |
|           |
|  #######  |
+===========+
```

Interior fill character by affliction ratio `r = remaining / initial`:

| `r`               | Fill char   |
| ----------------- | ----------- |
| `r > 0.75`        | `#`         |
| `0.75 ≥ r > 0.50` | `=`         |
| `0.50 ≥ r > 0.25` | `:`         |
| `0.25 ≥ r > 0`    | `.`         |
| `r == 0`          | ` ` (space) |

At `r == 0` the sigil is a hollow frame — the boss is gone, its container remains.

### 9.3 Constraints

- **ASCII only, U+0020–U+007E.** No Unicode box-drawing (U+2500 block), no block elements (U+2580 block). Guarantees identical advance width in IBM Plex Mono, in Martian Mono, and in every fallback mono on every platform. Box-drawing characters have inconsistent coverage and inconsistent advance in fallback fonts, and a sigil that mis-aligns looks broken, not retro.
- Rendered in a `<pre class="sigil" aria-hidden="true">`. Decorative — the boss name is the accessible label; a screen reader must not read `+===========+`.
- Font: **IBM Plex Mono** (the text face), 11px, `line-height: 11px` (exactly 1.0 so rows tessellate with no gaps), `letter-spacing: 0`, `font-variant-ligatures: none`.
- Colour: interior fill `--w1-status-null`; frame characters `--w1-green-700`. At `r == 0` the frame tweens to `--w1-green-500`.
- **Fixed box: 88 × 66 px.** It may never be enlarged, centred, given a glow, or made the focal point. If someone later wants a bigger boss visual, the answer is no — the grid is the boss.
- **No idle animation.** It changes only on a successful run: a 180 ms `power1.inOut` opacity cross-fade (`1 → 0.4 → 1`) as the fill character swaps. A continuously animating sigil would pull attention off the grid, which is exactly the failure mode this design avoids.

### 10.2 Closest real inspiration pattern

**itch.io indie game pages + the Awwwards "Developer" category, resolved through a specific archetype: the fixed-pane instrument panel.**

The concrete lineage this most resembles:

- **`htop` / `btop` TUIs** — the per-segment heatmap strip with height-encoded intensity is directly this.
- **Norton Commander / Midnight Commander** — the two-pane, full-viewport, no-scroll frame with 1px rules and no chrome.
- **DAW fixed-pane instrument UIs** (Ableton, Bitwig) — the whole viewport is one machine with fixed regions, never a scrolling document.
- **Fallout's Pip-Boy / amber-phosphor terminal props** — the CRT treatment and the P3 `#FFB000` amber, which is a real phosphor value, not an invented "retro orange."

Why this is the right reference class: all four are **"the entire screen is one instrument"** designs. The AI-generic fingerprint is fundamentally a _document_ — a scrolling page of stacked centred sections. This spec's single most anti-generic structural decision is `height: 100dvh; overflow: hidden` with internally-scrolling panels. That one rule makes almost every generic pattern structurally impossible: you cannot have a hero section, you cannot have fade-in-on-scroll, you cannot have a stacked card grid, because there is no scroll and no stack.

### 10.3 Drift caught and corrected during this spec

Four places where the first instinct was generic, and what replaced it:

1. **HP bar.** First instinct: a single aggregate bar with a green→red gradient fill that drains left-to-right. That is simultaneously the stock game-HUD default _and_ a red/green colour-blindness trap. **Replaced** with a per-row auto-binned heatmap using a single-hue lightness ramp plus height as an independent non-colour channel (§6) — which also happens to teach the player something real about where nulls cluster.

2. **Boss title.** First instinct: large centred title with a green text-shadow glow, floating above the grid. That is the hero pattern wearing a terminal costume. **Replaced** with a left-aligned 26px title inside the briefing panel next to an 88×66px ASCII sigil (§9), explicitly capped so it can never become the focal point.

3. **Afflicted cells.** First instinct: a pulsing `box-shadow` glow on each null cell. Banned twice over — soft ambient shadow is on §2's list, and blurred shadows on hundreds of virtualized cells is a real paint-cost problem. **Replaced** with an opacity-animated flat overlay pseudo-element plus a static 45° hatch and a dashed border (§5), which is compositor-cheap _and_ carries three independent non-colour signals.

4. **Diff colours.** Caught red/green as colour-blind-unsafe on its own. **Corrected** by shifting deletion to vermillion `#FF6B3D` (separable from the phosphor green under deuteranopia and protanopia) and making the `-`/`+` gutter glyph plus strikethrough mandatory on every flashed cell and every console line (§1.3, §7) — the same redundancy `git diff` itself relies on.
